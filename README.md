# Лабораторная работа №2

Учебное веб-приложение на **Python (только стандартная библиотека)** с двумя преднамеренными уязвимостями, скриптом эксплуатации и патчем. **Запускайте только локально**; приложение не предназначено для размещения на публичном сервере.

## Соответствие заданию

| Часть | Артефакт | Описание |
|---|---|---|
| 1 | `app.py` | Локальный HTTP-сервер, SQL Injection и Reflected XSS |
| 2 | `exploit.py` | Автоматизированная демонстрация обеих уязвимостей по HTTP |
| 3 | `fix.patch`, `app_patched.py` | Diff и полная исправленная версия |

Уязвимости в классификации **OWASP Top 10:2021**:

- **A03:2021 — Injection / SQL Injection.** Параметры `username` и `password` подставляются прямо в SQL. Полезная нагрузка `admin' -- ` превращает остаток условия в комментарий, позволяя войти без знания пароля.
- **A03:2021 — Injection / Reflected XSS.** Параметр `q` вставляется в HTML без экранирования. При открытии страницы с такой строкой браузер может выполнить внедрённый JavaScript.

Примечание: XSS входит в категорию Injection OWASP Top 10:2021. Если преподавателю нужны **две разные категории** OWASP, проект следует адаптировать.

## Требования

Python **3.9+**, сторонние пакеты не требуются. Примеры команд приведены для терминала из папки проекта.

## 1. Запуск уязвимой версии

```bash
python app.py
```

Откройте `http://127.0.0.1:8000/`.

## 2. Демонстрация эксплуатации

Во **втором терминале**:

```bash
python exploit.py
```

Ожидаемый результат:

```text
[OK] Неверный пароль отклонён (контрольная проверка).
[VULNERABLE] SQL injection: обход входа удался
[VULNERABLE] Reflected XSS: HTML-код отражён без экранирования

ИТОГ: SQLi=есть, XSS=есть
```

Скрипт обращается **исключительно** к `http://127.0.0.1:8000`, использует `urllib` и проверяет ответы HTTP.

Дополнительно можно протестировать вручную:

- В форме входа: логин `admin' -- `, пароль `wrong_password`.
- В форме поиска: `<script>alert('lab-xss')</script>`. При открытии результата в браузере возможен `alert`.

## 3. Применение патча и проверка

Остановите сервер (`Ctrl+C`). Для Linux/macOS/Git Bash:

```bash
patch -p1 < fix.patch
python app.py
```

Или без утилиты `patch` — запустите готовую исправленную версию:

```bash
python app_patched.py
```

Повторно запустите `python exploit.py`. Ожидаемый результат:

```text
[OK] Неверный пароль отклонён (контрольная проверка).
[PATCHED] SQL injection: обход входа не удался
[PATCHED] Reflected XSS: HTML-код не отражён как исполняемый HTML

ИТОГ: SQLi=исправлена, XSS=исправлена
```

**Что исправлено:** SQL-запрос теперь параметризован (отдельная передача значений через `?`), ввод пользователя перед вставкой в HTML экранируется через `html.escape(..., quote=True)`.

Если применили патч к `app.py`, повторно его применять не нужно. `app_patched.py` содержит ту же исправленную реализацию, что получается после патча.

## Размещение на GitHub / GitLab

Создайте **пустой** репозиторий и выполните:

```bash
git init
git add app.py app_patched.py exploit.py fix.patch README.md .gitignore
git commit -m "Add OWASP lab 2 vulnerable app, PoC and fixes"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/lab2-owasp.git
git push -u origin main
```

Замените `YOUR_USERNAME` на ваш логин, а адрес `origin` — на URL своего репозитория. В репозитории исходный `app.py` лучше оставить **уязвимым**, чтобы преподаватель мог отдельно применить `fix.patch` и сравнить поведение.

## Ограничения

Демо-логины и пароли фиктивные, база данных находится в памяти и сбрасывается при перезапуске. GET для передачи пароля выбран для краткости демонстрации и **не является безопасной практикой**. В реальных приложениях необходимы POST, безопасное хранение паролей и дополнительные защиты. Скрипт доказывает наличие небезопасного отражения HTML; выполнение JavaScript зависит от браузера и его политик безопасности.
